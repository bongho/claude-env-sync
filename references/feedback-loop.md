# 피드백 루프 규칙 (Feedback Loop Rules)

반복되는 실수를 감지하고, 규칙으로 체계화하여 학습합니다.

## 실수 감지 트리거

### 자동 감지 조건
| 트리거 | 조건 | 액션 |
|--------|------|------|
| 파일 재수정 | 동일 파일 3회 이상 수정 | "패턴 확인 필요" 알림 |
| 테스트 실패 | 동일 테스트 3회 이상 실패 | 근본 원인 분석 제안 |
| 빌드 실패 | 동일 에러 2회 이상 | 체크리스트 추가 제안 |

### 사용자 피드백 감지
- "이건 하지 마", "왜 계속 이래?"
- "아까 말했잖아", "다시 해"
- "항상 ~해줘", "~는 절대 하지 마"

## 규칙 추가 프로토콜

### 1. 분류 (Categorize)
| 카테고리 | 대상 규칙 파일 | 예시 |
|----------|---------------|------|
| 코딩 스타일 | `coding-style.md` | 포맷팅, 네이밍 |
| 보안 | `security.md` | 크레덴셜, 입력 검증 |
| Git | `git-workflow.md` | 커밋, 브랜치 |
| 테스트 | `testing.md` | 커버리지, TDD |
| 에이전트 | `agents.md` | 위임 조건 |

### 2. 초안 작성 (Draft)
```markdown
## 규칙 제안

### 배경
{문제 상황 설명 - 왜 이 규칙이 필요한가}

### 규칙
{구체적인 규칙 내용}

### Good 예시
```code
{올바른 예시}
```

### Bad 예시
```code
{잘못된 예시}
```
```

### 3. 승인 요청 (Approve)
- `AskUserQuestion`으로 규칙 추가 제안
- 사용자 승인 시 해당 규칙 파일에 추가
- 거절 시 이유 기록 후 대안 제안

### 4. 검증 (Verify)
- 다음 세션에서 규칙 적용 여부 모니터링
- 효과 없으면 규칙 수정 또는 제거 제안

## 규칙 우선순위

### Priority 1 - 필수 (Must)
- 보안 취약점 방지
- 데이터 무결성 보호
- 프로덕션 안정성

### Priority 2 - 권장 (Should)
- 코드 품질 향상
- 성능 최적화
- 유지보수성 개선

### Priority 3 - 선택 (May)
- 스타일 선호
- 편의 기능
- 개인화 설정

## 학습 루프 다이어그램

```
실수 발생 → 패턴 감지 → 규칙 초안 → 사용자 승인
    ↑                                      ↓
    ←←←←←← 검증 ←←←←←← 규칙 적용 ←←←←←←
```

## 에이전트 실패 패턴 기록 (KNOWN_ISSUES)

프로젝트별로 에이전트가 반복하는 실수 패턴을 기록하여 사전 방지한다.

### KNOWN_ISSUES.md 템플릿
```markdown
# Known Agent Issues

## 패턴 1: [실패 유형]
- **증상**: [에이전트가 보이는 행동]
- **원인**: [컨텍스트 부족 / 방향 오류 / 구조적 충돌]
- **처방**: [프롬프트 수정 / 파일 격리 / 가드레일 추가]
- **발생 횟수**: N회
```

### 실패 원인 분류 (3가지)
| 유형 | 원인 | 처방 |
|------|------|------|
| 컨텍스트 부족 | 필요한 정보가 프롬프트에 없음 | 관련 파일/규칙 명시 |
| 방향 오류 | 잘못된 방향으로 구현 진행 | Must NOT Have 가드레일 추가 |
| 구조적 충돌 | 코드 구조가 변경 의도와 맞지 않음 | 파일 격리, 인터페이스 분리 |

### 30분 룰
- 30분 내 진전 없으면 동일 접근 중단
- 다른 프롬프트, 다른 분해, 또는 수동 개입으로 전환

## 메타 규칙

### 규칙 충돌 시
1. 보안 규칙 > 성능 규칙 > 스타일 규칙
2. 프로젝트별 규칙 > 전역 규칙
3. 명시적 사용자 지시 > 모든 규칙

### 규칙 폐기 조건
- 3개월 이상 미적용
- 더 나은 대안 규칙 존재
- 사용자 명시적 폐기 요청
